## Decisions, and why

- **No keyword to start.** The number exists only for Baptize 2027, so any text starts or continues a signup. Asking people to text a keyword would just lose some of them.
- **The phone number is the identity:** one church per phone (`btw_churches.phone` is unique).
  - The user asked whether a second church from the same phone would be linked. It isn't; at worst RESTART after finishing wipes the first church's answers and starts over.
  - Multi-church per phone was proposed (NEW keyword, records keyed by id) and the user said **"nevermind"**: keep one church per phone.
  - The RESTART-wipes risk is known and accepted for now. The small fix offered was to make RESTART after DONE not wipe.
- **Language detection is conservative.** It needs 4+ letters, confidence 0.8+ and a switched-on language; otherwise the menu. First texts like "hi" are too short to guess. MENU switches language at any time and keeps the answers given so far.
- **Prompts are capped at 160 characters each.** The user's call ("we should not allow more than that many characters per entry box"). The cap is on raw characters, not SMS segments: a 160-character non-Latin prompt still goes as MMS, and that's accepted. Combined messages (menu, summary) still exceed it and go as MMS.
- **A long translation is fixed by shortening the English and translating again.** The user wanted to do that without leaving the other language's screen, hence "Edit English".
- **Reviewer messaging shares the signup number**, and there's no "open/close chat" switch; the user found that confusing. The rule instead:
  - Once a signup has been completed, any text that isn't a bot command goes to the team thread.
  - Mid-signup, texts go to the bot.
  - Reviewers can text anyone except opted-out numbers.
- **Translation both ways for team messages.** Incoming texts get an English translation; outgoing ones have an optional Translate button and the English stays visible.
- **Alerts:** only the unread badge in `/admin`. No email or text alert to reviewers yet (offered, not chosen).
- **Users all have the same rights.** That was the user's explicit requirement. Removing someone is soft (`active = false`) so their messages keep a name. `ADMIN_PASSWORD` became the cookie-signing key and a one-time setup password.
- **Editing answers never changes the texts.** The user's words: "the conversation would not change".
- **Simulations live in the real database**, so they show up in `/admin` exactly like real signups. They are flagged `simulated`, use fictional 555-01xx numbers, carry a badge, and are never texted. Add/Remove buttons are on the Conversations screen.
- **The map isn't ours to build.** A public map of churches "already exists" elsewhere, per the user; `public_map` is just stored.
- **Data retention:** no automatic cleanup. The user was told everything is kept until deleted; a retention rule was offered, not chosen.

## Working notes for the next session

- **Supabase MCP:** `execute_sql` reads and `apply_migration` work; DELETE through `execute_sql` timed out every time. Use the Delete button in `/admin` (or the API) to remove a conversation.
- **Vercel MCP:**
  - Can list deployments and read runtime logs (project `btw`).
  - It is **forbidden** from listing environment variables, so ask the user to check those.
- **No network to the site** from the sandbox: `btw-dusky.vercel.app` is blocked by the egress proxy. Test locally instead.
- **Local testing:** `node dev/server.mjs` runs the real handlers and pages against an in-memory database (`dev/fake-db.mjs`) with fake voip.ms and Google, on http://localhost:8787/admin (setup password `pw`). Playwright's Chromium is at `/opt/pw-browsers/chromium` for screenshots.
- **Stopping a background server:** don't `pkill -f "node server.mjs"` from the same shell line; the pattern matches the shell itself and kills the command. Use `pgrep -f "^node dev/server" | xargs -r kill`.
- **Migrations** are applied by hand through the Supabase MCP and also saved under `supabase/migrations/`. They only ever add columns or tables; nothing outside `btw_` is touched (shared project).
